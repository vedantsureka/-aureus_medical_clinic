# 17. IMPLEMENTATION ADDENDUM — SECURE ADMIN, REFRESH LOGOUT & PREMIUM MUMBAI UX

The original website specification above remains in full force. Implement the following additional requirements, rather than replacing any previous requirement.

## 17.1 Required deployable architecture

- Next.js App Router + TypeScript + React + Tailwind CSS; deploy from GitHub to Vercel.
- Supabase Postgres for doctor profiles, site settings, specialities, reviews, and appointment enquiries.
- Supabase Auth email/password for manually provisioned admin and doctor-authorised staff.
- Row-Level Security on every relevant table; the public never sees appointment records.
- Keep Supabase service-role credentials in private Vercel environment variables, never client-side.
- Include ready-to-run SQL, .env.example, README, and exact initial admin provisioning steps.

## 17.2 Private admin appointment dashboard

- Create `/admin` that requires valid Supabase Auth credentials **AND** a separately authorised staff role.
- No public sign-up or hardcoded admin username/password.
- Show appointment submissions with name, contact, doctor, consultation type, preferred date and preferred time, received timestamp, and pending/confirmed/cancelled status.
- Search patient names/numbers, filter by doctor/status and review optional patient note without publicly exposing it.
- Admin can update statuses and internal notes; patients do not have an appointment dashboard.
- Full-clinic admin can access both doctors; assigned doctor staff only sees their own appointments via database RLS.
- Support separate doctor timing settings and profile/content editing, with medically unverified information initially blank.
- Support updating services, individual doctor reviews, contact details and clinic notice.
- Do not imply that setting a status automatically texts or emails a patient unless a real notification integration is configured.

## 17.3 Force login again after every browser refresh

- After a successful admin login, keep the Supabase Auth session **only in memory**, not in localStorage, sessionStorage or cookies.
- Use `persistSession:false`, `autoRefreshToken:false` and `detectSessionInUrl:false` for admin browser auth client.
- Refreshing `/admin` (F5, reload) must show the login form again and never expose cached patient data. Verify it manually.
- Provide an explicit Logout control and add a 15-minute inactivity timeout as an extra safeguard.
- Explain accurately that refresh discards the local credential, but does not instantly revoke an already issued server JWT; RLS is essential.

## 17.4 Real appointment data protection

- Validate inputs on the Next.js server and normalise/validate Indian mobile numbers and dates.
- Use doctor-specific service types, mandatory privacy consent, clear 'appointment request pending confirmation' copy, minimal free-text fields and no patient file uploads.
- Add bot protection via Cloudflare Turnstile, plus honeypot and application-level safeguards.
- Protect the database with default-deny patient-enquiry RLS and allow only authorised roles to read/update.
- Handle failed submissions honestly; show success only after backend insert succeeds.
- Require an approved clinic privacy notice, operational data retention/deletion process and healthcare data compliance review before launch.

## 17.5 Premium Mumbai audience micro-interactions

- Emphasise Marine Lines East and the landmark opposite Wadia Fire Temple, with legible address, individual click-to-call numbers and a working Google Maps Directions shortcut.
- Desktop: airy editorial layouts, warm cream, navy, sage and restrained gold; balanced doctor cards and real verified clinic photography where available.
- Mobile: prominent fixed Call / Book / Directions bar, large accessible fields and buttons, no clutter and no horizontal overflow.
- Animate sections very slightly as they enter the viewport: about 25–40px upward movement, opacity from transparent to fully visible, soft easing over ~650–850ms, subtle 100–150ms stagger between cards.
- Allow a tiny delayed 'roll up' feeling as users scroll a wheel or touchpad, but **do not trap or hijack the natural scroll wheel**. Maintain responsive scrolling and honour `prefers-reduced-motion`.
- Add subtle button lifts, card hover movement, smooth in-page navigation and refined transitions without distracting medical patients.
- Ensure the front end remains tasteful, professional and reassuring for Mumbai patients of varying ages and abilities, not overly youthful or tech-heavy.

## 17.6 Acceptance checks

Deliver actual code that can be placed in GitHub and deployed on Vercel with Supabase. Demonstrate a patient enquiry for each doctor, verify database persistence and doctor-specific admin isolation, check that hard reload requires a new login, test mobile layouts and keyboard accessibility, and ensure no unverified medical claim is presented as fact.
